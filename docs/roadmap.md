# 开发路线

本路线按可交付能力拆分版本，落实事件可靠性、记忆受众、任务生命周期与预算控制。
当前实现的约束和限制见 [架构](architecture.md)。

## 版本总览

| 版本 | 核心交付 | 当前状态 |
|---|---|---|
| `0.1.0` | 离线基础工程 | 实现、离线验证与维护者审核已完成；不发 Release、不打标签 |
| `0.2.0` | 单平台真实文本应答 | 进行中：配置、文本入库与单实例生命周期已实现，真实应答待接通 |
| `0.3.0` | 带来源与受众控制的最小记忆闭环 | 待实现 |
| `0.4.0` | 第二平台文本应答与显式账户绑定 | 待实现 |
| `0.5.0` | 有资源和费用上限的图片输入 | 待实现 |
| `0.6.0` | 可关闭、可恢复的自主活动 | 待实现 |
| `0.7.0` | 一个只读工具与受控提示词改进 | 待实现 |
| `1.0.0` | 已支持组合的稳定运行与兼容承诺 | 待前述验收，不承诺日期 |

只并行推进当前版本需要的切片及必要的接口试验。第二平台的少量真实事件试验在 `0.3` 深入记忆前完成，
完整双平台链路在 `0.4` 验收；不等到复杂记忆已经固化后才验证核心契约能否复用。
每个版本晋级都需要实现、测试、适用的真实接入和发布记录各自的证据。

文档整理不会自动把软件版本提升为 `0.2`。

## 0.2.0：单平台真实文本应答

目标是一个吟子实例、一个 OneBot V11 协议端、一个专用会话、一个已验证模型端点的真实往返。
默认采用混合行为：响应白名单内的私聊和定向请求，主动社交保持关闭。

按依赖顺序交付，每一步通过检查后独立签名提交：

- [x] 运行配置：显式测试目标、行为模式、模型接口、价格和硬预算；加载审核版本的人格与可信关系配置，
  提供离线 `check-config`。实际协议端与模型端点的可用性由后续接入验收。
- [x] 薄接入：OneBot 文本归一化、稳定 source_event_id、持久入库和唤醒；平台 SDK 留在适配器内。
  NoneBot 调度与存储故障已验收，反向 WebSocket 启停、鉴权和重连随生命周期步骤验收。
- [x] 生命周期：实现数据目录独占及唯一 worker/sender，明确接入、处理、发送的启停顺序；
  完整决策的总时间受活动租约和截止时间约束，过期/取消计算不得提交。
  采用合成决策完成实际本机 WebSocket 测试；真实模型重试与生产发送策略仍由后续步骤验收。
- [ ] 模型入口：每次真实付费尝试先预留，再根据可信用量结算；涵盖解析失败后的允许重试、拒绝、空响应、
   流式中断和未知用量。首个提供方只实现实测需要的 Schema 适配和本地严格校验。
- [ ] 文本决策：人格与获准上下文 → 有界文本决策 → 业务校验 → 原子提交 outbox；
   默认中文、外语语境和关系称呼进入人工探针。
- [ ] 实际发送：永久失败、限流等待、投递截止时间、回执确认和 unknown 查询/人工核对；
   未知投递不能因重启或收到重复事件而重新发送。
- [ ] 运行验证：记录 trace、尝试 ID、用量和终态，完成安装、停启、故障演练与候选观察；
   凭据和真实消息保存在忽略目录，不进入发布包。

完成标准：专用会话真实文本往返；重推事件不重复提交决策或出站；入站落库后重启可恢复；
发送回执丢失不盲目重发；日/月额度耗尽后所有付费入口拒绝新调用；模型响应与打字等待期间仍能收包；
完成人格初步人工评审和受控运行观察。

## 0.3.0：最小记忆闭环

- [ ] 先用选定第二平台的少量脱敏真实事件检查完整会话命名空间、重推和平台能力差异，修正契约后再深化记忆。
- [ ] 基于持久事件建立 L1 事实存储，保留来源、证据类型、有效时间，区分重要度与可信度。
- [ ] 查询层先过滤 agent 与受众，再检索和装配上下文；初期采用有界的 SQLite 查询，向量检索按效果需求增加。
- [ ] 最小自动抽取与一次摘要经结构校验、来源核对和可信受众规则后写入；模型不能自行授予共享权限。
- [ ] 实现事实更正、历史查询、消息撤回、授权撤销、删除和派生记忆失效；画像与摘要继承来源限制。
- [ ] 用固定样本比较无记忆基线，报告事实检索、纠错和权限结果，控制抽取、摘要及评测费用。

完成标准：记得有证据的事实、能更正并查询旧状态；私聊记忆不会进入群聊模型输入，跨群和跨 agent 同样隔离；
来源撤回或共享撤销后，旧摘要不能继续暴露内容；更正与删除在重启后仍有效。
语言质量使用样本和人工评审说明，不用少量题目的提升宣称泛化效果。

## 0.4.0：第二平台文本与身份绑定

- [ ] 接通契约试验时选定的 Telegram 或 Discord，复用事件、worker、预算、记忆和 outbox。
- [ ] 以可信核验建立账户归属映射，提供显式共享及可撤销授权；绑定本身不扩大记忆受众。
- [ ] 记录各平台实际支持的编辑、撤回、回执、历史补拉和限流语义，未提供的能力明确列为限制。

完成标准：两个平台均完成文本往返与重启恢复；相同原生 ID 不碰撞；绑定后的账号仍不能跨受众检索私聊资料；
显式授权只开放指定目标，解绑与撤销按既定规则收回权限。每个平台有独立的发送不确定结果演练记录。

## 0.5.0：受限图片输入

- [ ] 首先支持图片输入和文本回答，保留消息及图片来源；历史图片是否再次加载由有界上下文策略决定。
- [ ] 根据实测模型能力约束真实 MIME、单图像素、图片数、总字节数和费用；不照搬上游 4096/8192 的阈值。
- [ ] 补齐资源到期、清理、授权撤销和加载失败的可观测处理，明确超限时拒绝图片或仅文本处理的策略。
- [ ] 对每次包含历史图片的调用重新估算并预留费用；图片提取的事实遵守 `0.3` 来源与受众规则。

完成标准：支持组合通过真实图像问答；格式声明与字节匹配，超限和坏图不会静默越过策略；
资源删除、权限撤销和预算耗尽后，后续调用不能继续携带相应图片。
语音、视频与动态图片生成继续后置。

## 0.6.0：受控自主活动

- [ ] 定时器只生成持久活动，处理巡检合并、过期取消、累计尝试与有界恢复；会话停留以 next_run_at 表达。
- [ ] 增加冷却、静默时段、按会话关闭入口和主动消息截止时间，保留定向请求响应通道。
- [ ] 概率门先通过固定种子的离线模拟和单位、跨午夜边界检查；活动频率由可信配置控制。
- [ ] 运行状态只更新允许变化的情绪、疲劳和当次活动；人格倾向与锚定规则保持维护者审核边界。

完成标准：忙碌时的持久活动有明确去向，重启不突发补发过期主动消息；关闭或静默后不主动打扰；
主动活动、状态更新和相关模型调用都受统一预算约束，定向响应不被概率门挡住。

## 0.7.0：只读工具与受控改进

- [ ] 接一个实际需要的只读查询工具，明确输入/输出、权限、超时、结果来源和预算，不预建未使用的工具生态。
- [ ] 固定人格漂移、事实和对话质量探针，人工校准评审结果，普通记忆写入与提示词发布采用不同评测强度。
- [ ] 候选提示词在隔离记忆和角色状态的影子实验中评估，不能发消息或写生产记忆；费用仍计入统一账本。
- [ ] 人格或提示词候选经维护者审核后随整体版本发布，并能切回上一组合；候选失败不会污染当前人格。

完成标准：工具调用越权与超时有终态，候选效果有可复现样本；影子实验副作用被隔离，实际执行过一次版本回退。
不包括模型权重训练、自动生效的人格演化或通用代码执行。
