# 0.1.0 发布准备

`0.1.0` 是离线基础工程版本，尚未正式发布。本文说明交付范围、验证门槛和发布前剩余工作；
正式发布时补充最终提交、签名标签、验证结果及产物摘要。

## 交付范围

| 项目 | 范围 |
|---|---|
| 软件 / 人格 / SQLite schema | `0.1.0` / `1.0.0` / `1` |
| 运行环境 | Python 3.13，使用 uv 与锁文件管理依赖 |
| 交付形式 | sdist 与 wheel |
| 已实现能力 | 统一文本事件、SQLite inbox/outbox 与租约、记忆受众策略、持久预算账本、人格资源加载及离线命令 |
| 发布工具 | 显式打包清单、版本及源码一致性核对、SHA-256、独立环境安装验证和 CI 产物留存 |
| 未接入能力 | 真实平台与模型、记忆存储、自动抽取、自主活动、容器及自动升级 |

受众策略和预算账本是可测试的核心原语，不代表真实记忆查询或模型调用已经受其约束。
人格的真实模型表现仍待评审。原创代码采用 AGPL-3.0-only；人格及第三方组件的分发范围见
[许可与来源](../licensing.md)。

## 验证门槛

从干净检出执行 [发布方案](../release-plan.md#每个版本都必须通过的门槛) 中的完整检查，
分别记录 Windows 与 Linux 结果。至少包括锁定依赖安装、Ruff、pytest、离线 smoke、
sdist / wheel 构建和源码目录外的独立安装检查。

验包工具为每次构建生成 `dist/verification.json` 与 `dist/SHA256SUMS`，记录版本、产物清单、
摘要、构建来源和安装检查结果。CI 按操作系统保存对应报告和产物。报告只证明其对应的提交与构建，
不能将带工作区修改的结果作为最终签名提交的发布证据。

安装构建出的 wheel 后，`ginko doctor`、`ginko smoke` 和 `ginko persona` 必须通过。
`smoke` 使用临时 SQLite 和合成数据，不读取现有聊天记录，也不发起付费调用或平台发送。
`0.2.0` 的真实文本往返、候选运行观察、人格人工探针和平台故障演练不属于本版离线验收范围。

## 数据与回滚边界

本版没有上一正式发布版，也没有数据库迁移器。只允许创建或打开 schema `1`，其他版本必须拒绝。
备份前关闭所有连接，或使用 SQLite 一致性备份接口；活跃 WAL 不能只复制主文件。

只有数据兼容时才能切回旧代码；不能通过降低 schema 版本号强行回退。
任何数据恢复都不能重发 `sent` / `unknown` 投递、清空未知用量预留或重置累计尝试次数与截止时间。
完整升级及恢复约束见 [发布方案](../release-plan.md#升级与回滚)。

## 正式发布前剩余工作

- 维护者审核版本范围、人格资源及其分发授权，并登记审核结果。
- 形成最终签名发布提交，从干净检出重新检查、构建和验包，记录最终提交、环境、结果与产物摘要。
- 审核最终产物后创建签名标签 `v0.1.0`，保存该提交对应的归档与验证报告。
- 确定发布目标与分发渠道，只上传通过核对的产物。

正式标签不移动，正式产物不覆盖。完成这些门槛前，版本状态保持未发布。
